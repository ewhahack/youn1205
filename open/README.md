# 나라장터 자체입찰 공고 법령 위반사항 모니터링 AI 경진대회

## 데이터 및 제출 형식 안내

입찰공고 1건의 공고문, 첨부 문서 및 나라장터 등록 정보를 바탕으로 24개 검토 항목의 위반 여부와 근거 문구를 판정하는 과제입니다.
이 문서는 배포 데이터와 제출 형식을 설명합니다. 대회 규칙, 일정 및 평가 환경은 대회 페이지의 공지를 따릅니다.

## 1. 빠른 시작

배포 폴더에서 다음 명령을 실행하면 모델을 불러오지 않고 입력부터 제출 파일 생성까지의 흐름을 확인할 수 있습니다.

```bash
python3 baseline/script.py --mock
```

생성 파일은 `output/submission.csv`입니다.

## 2. 제공 파일

| 파일 | 규모 | 용도 |
|---|---:|---|
| `train_unlabeled.jsonl.gz` | 20,000건 | 라벨 미제공 입찰공고입니다. 라벨이 없다는 이유로 위반이 없는 공고로 간주할 수 없습니다. |
| `dev.jsonl.gz` · `dev_labels.csv` | 200건 | 입력·라벨·근거 문구 형식을 확인하기 위한 예시입니다. 평가 데이터의 분포를 대표하지 않습니다. |
| `data/test.jsonl.gz` | 10건 | 로컬 실행과 형식 확인을 위한 샘플 입력입니다. |
| `data/항목표.json` | 24개 항목 | 항목명, 관련 조문, 부재탐지 여부 및 참고사항을 제공합니다. |
| `data/정답스키마_디코딩.json` | — | 베이스라인의 구조화 출력에 사용하는 JSON Schema입니다. 정답 값은 포함하지 않습니다. |
| `data/법령패키지/` | — | 판정 기준이 되는 법령·행정규칙 텍스트와 고시 자료입니다. 텍스트 변환이 제한된 구간은 각 파일에 표시되어 있습니다. |
| `sample_submission.csv` | 10행 | 49열 제출 형식 예시입니다. |
| `baseline/` | — | `script.py`와 `requirements.txt`로 구성된 코드 제출 예시입니다. |

평가 서버에서는 실제 평가 입력이 `data/test.jsonl.gz` 경로에 제공됩니다. 입력 파일의 `id`와 행 수를 읽어 그대로 출력해야 하며, 샘플의 ID 형식이나 건수를 하드코딩해서는 안 됩니다.

## 3. 입력 데이터 형식

JSONL 한 줄이 입찰공고 1건입니다. 라벨 미제공 데이터, dev 데이터 및 평가 데이터는 같은 레코드 구조를 사용합니다.

| 키 | 형식 및 의미 |
|---|---|
| `id` | 공고 식별자입니다. 제출 파일의 `id`에 그대로 사용합니다. |
| `docs` | `doc_id`, `type`, `text`로 구성된 문서 배열입니다. `type`은 공고문·규격서·과업지시서·제안요청서·예외공표서 중 하나이며, `text`는 NFC로 정규화되어 있습니다. 표 구분에는 `\|`가 사용될 수 있습니다. |
| `meta` | 나라장터 등록 정보 21개 필드입니다. |
| `dropped_doc_counts` | 입력 길이 제한으로 제외된 문서의 종류와 개수입니다. |
| `input_completeness` | 공고문 실재 여부, 추출 성공 여부, 문서 탈락 여부 및 완전관측 여부를 나타냅니다. |
| `anon_applied` | 익명화 적용 여부입니다. 배포 데이터는 `true`입니다. |
| `assembly_policy_version` | 레코드 조립 규약의 버전입니다. |

각 레코드에는 공고문이 1건 이상 포함됩니다. 판정 시 제공된 첨부 문서도 함께 확인해야 합니다. `dropped_doc_counts`가 비어 있지 않다면 제공되지 않은 문서가 있음을 고려해야 합니다.

## 4. `meta`와 익명화

`meta`에는 다음 정보가 포함됩니다.

- 계약·입찰: 적용계약법, 업무구분, 계약방법, 낙찰방법, 낙찰하한율, 입찰방법, 조달방식
- 금액·일정: 배정예산금액, 입찰추정가격, 공고게시일자, 개찰예정일자, 긴급공고여부
- 자격·제한: 소관구분, 공동도급구성방식, 정보화사업여부, 세부품명번호목록, 제한지역코드목록, 지역제한여부, 면허업종제한목록, 업종제한여부, 조항호내용

값이 없으면 `null`, 나라장터에 등록되지 않은 값은 `"미입력"`으로 표시됩니다. 두 값은 서로 다르며 `"해당 없음"`을 의미하지 않습니다.

`v24`는 공고 문서와 나라장터 등록 정보의 불일치를 확인하는 항목이므로, 문서와 `meta`가 다를 수 있습니다.

기관명, 담당자, 연락처, 주소 및 공고번호는 익명화 토큰으로 치환되어 있습니다. 예를 들어 `[수요기관(기초자치단체)|지역=r1]`에는 기관 유형이, `[지역:r1|단위=기초|광역=경기도]`에는 지역 계층이 표시됩니다. 같은 문서에서 `r1`과 `r2`는 서로 다른 지역을 뜻합니다. 금액, 수량, 날짜, 법령 조문, 품명 및 규격은 치환 대상이 아닙니다.

## 5. 제출 형식

출력 파일은 `output/submission.csv`이며, 헤더는 `id,v1..v24,e1..e24`의 49열입니다. 행 수는 입력 건수와 같아야 합니다.

| 열 | 규칙 |
|---|---|
| `id` | 입력 레코드의 `id`를 그대로 사용합니다. |
| `v1`~`v24` | 정수 `0` 또는 `1`만 허용합니다. 공란, `true`, 문자열 `"1"`은 허용하지 않습니다. |
| `e1`~`e24` | 위반으로 판정한 근거 문구를 입력합니다. 제공된 문서에 존재하는 부분문자열을 그대로 사용하며 500자 이하여야 합니다. 비위반 항목은 빈칸으로 둡니다. `v10`, `v11`, `v16`, `v18`, `v20`은 부재탐지 항목이므로 항상 빈칸으로 둡니다. |

파일 형식은 다음 기준을 따릅니다.

- UTF-8, BOM 없음
- NFC 정규화
- CSV 필드 인용 규칙 적용
- 근거 문구가 `=`, `+`, `@`로 시작하지 않도록 처리

리더보드 점수는 24개 항목별 양성 클래스 F1의 단순 평균인 Macro F1입니다. 근거 문구는 리더보드 점수에 반영되지 않으며 2차 정성평가 자료로 사용됩니다.

## 6. 실행환경 및 주의사항

- 고정 모델 `google/gemma-4-26B-A4B-it`은 평가 서버의 `PPS_MODEL_DIR` 경로에 제공됩니다. 베이스라인은 vLLM offline API로 모델을 불러옵니다.
- vLLM의 하위 프로세스 실행을 위해 모델 실행 코드는 `if __name__ == "__main__":` 아래에 두어야 합니다.
- 제출 ZIP에는 LLM 가중치와 LoRA 어댑터를 포함할 수 없습니다. `model/`에는 실행에 필요한 정적 자산만 포함할 수 있습니다.
- `vllm`, `torch`, `transformers`, `xgrammar`는 평가 서버 고정 패키지이므로 `requirements.txt`에서 다른 버전으로 변경할 수 없습니다.
- 보조 임베딩 모델 `BAAI/bge-m3`는 `PPS_EMBED_DIR` 경로에 제공됩니다.
- 패키지 설치 단계에서는 네트워크를 사용할 수 있으나 `script.py` 실행 중에는 인터넷 연결이 차단됩니다.
- 제공 자료 외부의 공고 원문·메타데이터를 수집하거나 익명화된 식별자를 복원하는 행위와 비공개 평가 데이터를 이용한 추가 학습·Pseudo-Labeling은 허용되지 않습니다.
- 판정에는 배포된 `data/법령패키지/`의 스냅샷을 기준으로 사용합니다.

세부 제한과 예외는 대회 페이지의 공식 규칙을 확인하십시오.
